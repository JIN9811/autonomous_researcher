# Analysis UTM Runtime Guideline

Status: implementation guideline
Last reviewed: 2026-09-02
Scope: Analysis Agent UTM curve processing for test and live autonomous runs.
Related: `cae_analysis_runtime_guideline.txt` for CAE closed-loop simulation data.

## 1. Purpose

Analysis Agent owns post-equipment mechanical data reduction.

Pipeline position:

```text
Specimen Making -> Vision -> Manipulation -> Lab Equipment -> Analysis -> Knowledge -> Guardian
```

The agent must preserve UTM force/displacement evidence, convert it to an
engineering stress/strain response using the planned initial specimen
geometry, and produce mechanical metrics, an objective score, uncertainty,
and a compact operator-facing summary.

## 2. Accepted UTM Inputs

Analysis Agent reads the latest Lab Equipment output from:

```text
state.run_metadata.equipment_result
```

Accepted inline curve keys:

- `utm_data`
- `utm_curve`
- `curve`
- `measurements`
- `samples`
- `data`
- `raw_data`

Accepted file keys:

- `result_file`
- `result_path`
- `csv_path`
- `utm_result_file`
- `utm_csv_path`
- `artifact_path`

Supported file formats:

- CSV with headers
- Numeric CSV with displacement/force as the final two columns
- JSON list of rows
- JSON object containing any accepted inline curve key
- JSONL rows

Column aliases:

- displacement: `displacement_mm`, `extension_mm`, `stroke_mm`,
  `crosshead_mm`, `position_mm`, `displacement`, `extension`
- force: `force_N`, `load_N`, `force`, `load`
- time: `time_s`, `time_sec`, `seconds`, `time`

## 3. Specimen Geometry Inputs

The agent derives geometry from `state.current_experiment_spec`, with
`specimen_result.candidate.parameters` used as an additional source when
available.

Required or defaulted fields:

- `specimen_size_mm`: defaults to `[20, 20, 20]`
- `cross_section_area_mm2`: defaults to `size_x * size_y`
- `gauge_length_mm`: defaults to `size_z`
- `expected_mass_g` or `measured_mass_g`: optional, used for specific energy

Engineering normalization uses the initial apparent geometry:

```text
sigma_eng = force_N / cross_section_area_mm2       [MPa]
epsilon_eng = displacement_mm / gauge_length_mm    [1]
V0 = cross_section_area_mm2 * gauge_length_mm      [mm3]
```

Compression is positive. An explicitly supplied zero, negative, or non-finite
area/height is invalid and blocks normalized analysis; it is not replaced with
a fallback value.

## 4. Computed Metrics

Analysis Agent computes:

- `peak_force_N`
- `displacement_at_peak_mm`
- `initial_stiffness_N_per_mm`
- `compressive_strength_MPa`
- `apparent_modulus_MPa`
- `strain_at_peak`
- `energy_absorption_mJ`
- `energy_density_mJ_per_mm3`
- `specific_energy_absorption_J_per_g`
- `energy_absorption_50pct_mJ`
- `energy_density_50pct_MJ_per_m3`
- `energy_identity_relative_error`
- `curve_quality`

When `cae.run_static_analysis` is registered, Analysis Agent also records:

- `cae_result`
- `cae_metrics`
- `closed_loop_sources`

Default CAE setup:

- bottom face fixed support
- top face cyclic compression loading

Energy unit note:

```text
1 N*mm = 1 mJ
integral(sigma_eng d epsilon_eng) = mJ/mm3 = MJ/m3
energy_absorption_50pct_mJ = V0 * energy_density_50pct_MJ_per_m3
```

The 50% boundary is `epsilon_eng=0.5`. Analysis interpolates at the exact
boundary when measured points bracket it, never extrapolates, and does not
smooth lattice-collapse serrations.

## 5. Objective Score

The agent writes:

```json
{
  "analysis": {
    "objective_score": 0.0,
    "uncertainty": 0.0,
    "utm_metrics": {},
    "summary": "..."
  }
}
```

Objective mapping:

- objective names containing `strength` or `peak` emphasize compressive strength
- names containing `stiff` or `modulus` emphasize apparent modulus
- names containing `energy` or `absor` emphasize energy absorption
- otherwise use a weighted strength/modulus/energy composite

If CAE succeeds, the final objective blends UTM and CAE:

- 75% UTM-derived objective
- 25% CAE structural score

This lets test-mode closed-loop runs use simulation data without replacing the
primary UTM-derived metrics.

When no compiled objective is active, the BO-facing default is
`energy_density_50pct_MJ_per_m3` with unit `MJ/m3` and direction `maximize`.
The total `energy_absorption_50pct_mJ` remains available for dimensional
cross-checks and absolute specimen-energy reporting.

### 5.1 Compiled Objective Runtime

When `state.current_experiment_objective` requests `objective_spec.v1`, an
active run binding is mandatory. Analysis resolves the shared
`objective.service`, maps only Metric Registry source paths to registered
metric ids, and performs deterministic evaluation. The LLM is not used to
calculate the score.

The evaluation emits `objective_evaluation.v1` with objective id/version/hash,
observation id, finite score, feasibility, term contributions, constraint
results, uncertainty, metric values, provenance references, and fidelity.
The same record is embedded in `analysis`, `bo_observation`, `bo_handoff`, and
the Knowledge payload. Missing service/binding or a requested hash/id mismatch
blocks objective evaluation with `OBJECTIVE_BINDING_REQUIRED` or
`OBJECTIVE_BINDING_MISMATCH`; it must not fall back to the legacy keyword
score. The legacy score remains available only when no compiled objective was
requested.

## 6. Test Mode

Test mode behavior:

- If inline/file UTM data exists, parse and analyze it.
- If no UTM data exists, generate a deterministic synthetic UTM curve from
  specimen size, relative density, and wall thickness.
- Mark synthetic data source as `synthetic_test_utm_curve`.
- Keep uncertainty higher than real data because the curve is simulated.
- Run `cae.run_static_analysis` when available.
- Add successful CAE results to `analysis.cae_metrics`.
- Include `cae.run_static_analysis` in `analysis.closed_loop_sources`.

This lets Main GUI test mode and Live GUI test-mode runs exercise the full
Analysis -> Knowledge -> Guardian path without real UTM hardware while still
using CAE data for closed-loop objective scoring.

## 7. Live Mode

Live mode behavior:

- Do not fabricate UTM data.
- Require inline UTM data or a readable result file.
- If data is missing, return `analysis.ok=false` with
  `failure_code=UTM_DATA_REQUIRED`.
- CAE may be attempted and reported, but it must not hide missing live UTM data.
- Validation must block stage progression, causing retry/error rather than
  updating Knowledge with fake metrics.

## 8. Main Loop Integration

RunLoop stores Equipment outputs before Analysis:

- `run_metadata.equipment_result`
- `run_metadata.equipment_handoff`
- `latest_analysis.equipment_ok`
- `latest_analysis.equipment_status`
- `latest_analysis.equipment_program_id`

Analysis Agent then returns:

- `analysis.ok`
- `analysis.source`
- `analysis.utm_metrics`
- `analysis.utm_curve`
- `analysis.stress_strain_curve`
- `analysis.cae_result`
- `analysis.cae_metrics`
- `analysis.closed_loop_sources`
- `analysis.specimen_geometry`
- `analysis.objective_score`
- `analysis.uncertainty`
- `analysis.recommendation`
- `analysis.summary`

## 9. Safety Rules

- Never hide missing live UTM data behind synthetic results.
- Never update Knowledge/Guardian with failed live UTM analysis.
- Keep raw full curves out of chat-sized summaries; return a compact preview.
- Preserve bucket-local stress extrema in the compact S-S preview; do not
  smooth away physical load drops.
- Preserve objective and uncertainty keys because Knowledge and Guardian depend
  on them.

## 10. Improvement 06 Runtime Contract

Analysis Agent now owns the full raw-to-BO handoff path:

```text
raw UTM/equipment artifact
-> file fingerprint + parser report
-> column/unit mapping
-> canonical force/displacement curve plus engineering stress/strain curve
-> preprocessing report
-> quality gate
-> UTM metrics
-> optional CAE/CalculiX simulation evidence
-> FEM/UTM comparison
-> previous/best comparison
-> experiment_evaluation.v1
-> analysis_bo_handoff_v2
```

Generated run artifacts are written under:

```text
runs/<run_id>/analysis/<specimen_id>/
```

Expected artifact files:

- `raw_input_sidecar.json`
- `parse_report.json`
- `canonical_curve.csv`
- `preprocessing_report.json`
- `quality_report.json`
- `metrics.json`
- `fem_request.json` when CalculiX is available
- `fem_result.json`
- `fem_utm_comparison.json`
- `comparison.json`
- `analysis_report.json`
- `experiment_evaluation.json`
- `bo_handoff.json`
- `analysis_trace.jsonl`

The BO-facing payload is available as both:

- `result.data["bo_observation"]` with schema `bo_observation.v1`
- `result.data["bo_handoff"]` with schema `analysis_bo_handoff_v2`

`experiment_evaluation.v1` is also emitted so the controller can append it to
`state.experiment_evaluations` and BO/Knowledge can consume measured history.

The default BO observation carries only
`energy_density_50pct_MJ_per_m3`. `energy_absorption_50pct_mJ`, the raw F-D
preview, the compact S-S preview, and the full canonical CSV remain in the
Analysis evidence layer. An activated compiled objective overrides this default
without changing its approved hash or unit.

## 11. CAE / CalculiX Simulation Evidence

Analysis Agent may attach CAE simulation evidence through the registered CAE bridge. The documented solver direction is CalculiX-oriented, while the separate Python FEM solver stack is removed from the active install path.

Registered CAE tool:

```text
cae.run_static_analysis
```

Fidelity separation is mandatory:

- UTM curve = `utm_high`, physical/measured objective source.
- CAE/CalculiX result = `fem_low`, simulation/risk/calibration evidence.
- FEM/CAE prediction must not be inserted into BO as if it were a measured UTM point.

The detailed CAE runtime contract is maintained in `docs/agents/cae_analysis_runtime_guideline.txt`.
