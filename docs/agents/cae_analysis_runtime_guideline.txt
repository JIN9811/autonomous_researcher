# CAE Analysis Runtime Guideline

Status: implementation guideline
Last reviewed: 2026-09-02
Scope: Analysis Agent, CAE facade, Gmsh, CalculiX, and BO comparison handoff.

## 1. Runtime role

CAE Analysis estimates the compression response before or alongside a physical
UTM run. Physical UTM data remains authoritative. The real solver path and the
solver-free test path share curve and metric names, but always expose different
`solver_mode` values so derived evidence cannot be mistaken for measurement.

```mermaid
flowchart LR
    P[Experiment plan<br/>height, size, material] --> A[Analysis Agent]
    S[Generated specimen STL] --> A
    A --> C{CAE mode}
    C -->|test| E[Deterministic nonlinear<br/>cellular equivalent]
    C -->|live + execution gate| G[Gmsh volume mesh]
    G --> X[CalculiX nonlinear static step]
    E --> M[Canonical force-displacement curve]
    X --> M
    U[Lab Equipment Agent<br/>UTM CSV] --> Q[UTM parser and metrics]
    M --> K[Three-metric comparison]
    Q --> K
    K --> B[BO handoff]
```

## 2. Mechanical model

The production analysis is displacement-controlled quasi-static compression.

| Item | Definition |
|---|---|
| Initial height | `specimen_size_mm[2]` from the experiment plan |
| Target | `target_strain * initial_height`, default `0.5` |
| Bottom face | `U3=0`; `U1/U2` free |
| Top face | prescribed negative `U3`; `U1/U2` free |
| Rigid-body stabilization | one bottom node fixes `U1/U2`, a separated node fixes `U2` |
| Platens/contact | not modeled |
| Procedure | `*STEP,NLGEOM` + `*STATIC`, automatic increments |
| Load history | named linear displacement amplitude |
| Material | isotropic elastic and optional multilinear plastic data |

“Frictionless” means the complete top and bottom node sets are constrained only
in the compression axis. The three in-plane stabilizer DOFs belong to two
individual bottom nodes and are recorded separately in the deck manifest.

The current model deliberately omits platen solids, contact, friction,
self-contact, and dynamics. At large strain this permits geometric
interpenetration, so a completed calculation is a model result, not automatic
experimental validation.

## 3. Public tool contract

Registered tools:

- `cae.health`
- `cae.run_static_analysis`
- `calculix.health`
- `calculix.prepare_input`
- `calculix.solve`
- `calculix.postprocess`
- `calculix.run_job`

Recommended `cae.run_static_analysis` payload:

```json
{
  "runtime_mode": "test",
  "runtime_solver_enabled": false,
  "specimen_id": "specimen-001",
  "stl_path": "/path/to/specimen.stl",
  "specimen_size_mm": [30.0, 30.0, 30.0],
  "mesh_size_mm": 2.0,
  "material": {
    "elastic_modulus_mpa": 1800.0,
    "poisson_ratio": 0.35,
    "yield_strength_mpa": 35.0,
    "plastic_curve": [[35.0, 0.0], [42.0, 0.08]]
  },
  "loading": {
    "load_type": "quasistatic_compression",
    "loading_control": "displacement",
    "target_strain": 0.5,
    "initial_increment": 0.01,
    "minimum_increment": 1e-7,
    "maximum_increment": 0.02,
    "max_increments": 500
  },
  "boundary": {
    "bottom": "frictionless_axial_support",
    "top": "frictionless_displacement"
  }
}
```

The legacy `boundary_condition=bottom_fixed_support` and
`loading_mode=top_cyclic_loading` labels remain response aliases for older GUI
and run records. The authoritative mechanical description is `boundary`, the
deck manifest, and `analysis_platens.bottom/top=false`.

Core response fields are:

- identity: `specimen_id`, `mode`, `solver_mode`, `analysis_type`;
- target: `target_strain`, `target_displacement_mm`, `loading_control`;
- curve: `reaction_force_displacement_curve` using positive compression signs;
- metrics: peak reaction force, initial stiffness, 50%-height energy, endpoint
  status, and converged increment count;
- provenance: solver health/version, step trace, mesh/deck/DAT/FRD/curve paths;
- status: `ok`, `status`, `failure_code`.

`N*mm` is numerically `mJ`, so trapezoidal curve integration directly produces
`energy_absorption_50pct_mJ`.

## 4. Test mode

Test mode never starts Gmsh or CalculiX. It produces a 101-point nonlinear
cellular proxy with elastic, collapse-plateau, and densification regimes. The
scaling uses material modulus/yield strength, relative density, wall-to-cell
ratio, specimen area, and planned height. It is labelled
`deterministic_quasistatic_equivalent`.

The temporary unmatched UTM CSV may be used only to check order of magnitude.
Its energy, peak, or stiffness must not appear as fitted constants. Test-mode
artifacts under `artifacts/cae` contain normalized input, report JSON, curve
JSON, and an explanatory contour SVG.

## 5. Live mode

Live mode delegates to `CalculiXBridge` only when all of these are true:

1. mode is `live`;
2. CalculiX and Gmsh are available;
3. the request explicitly sets `runtime_solver_enabled=true`;
4. a readable STL is supplied.

Installation does not arm execution. `runtime_solver_enabled` remains a
per-request operator gate.

The real sequence is:

```text
STL -> direct discrete-surface volume mesh -> boundary node sets
    -> nonlinear CalculiX deck -> ccx -> DAT/FRD
    -> canonical curve -> peak/stiffness/energy
```

The source STL is not modified. Direct discrete-surface meshing avoids the
expensive `ClassifySurfaces/CreateGeometry` remeshing path, which is unsuitable
for dense TPMS STL files and can introduce invalid overlaps after decimation.

## 6. Installation and health

This workstation uses user-local ARM64 package extraction because system
package installation requires administrator credentials:

```text
CalculiX wrapper: /home/jin/.local/bin/atr-ccx
Gmsh wrapper:     /home/jin/.local/bin/atr-gmsh
Runtime library:  /home/jin/.local/opt/atr-cae/usr/lib/aarch64-linux-gnu
```

The wrappers set `LD_LIBRARY_PATH` and execute CalculiX 2.21 and Gmsh 4.12.1.
`calculix.health` reports resolved paths and version strings. Another host may
instead configure `/usr/bin/ccx` and `/usr/bin/gmsh` or rely on `PATH`.

## 7. Failure and partial-result rules

| Condition | Required result |
|---|---|
| Missing STL | `CAE_STL_REQUIRED` |
| Missing Gmsh | `CAE_GMSH_REQUIRED` |
| Mesh error/empty volume | `CAE_MESH_FAILED` |
| Runtime gate off | `CALCULIX_RUNTIME_SOLVER_DISABLED` |
| Missing CalculiX | `CALCULIX_EXECUTABLE_REQUIRED` or facade `CAE_SOLVER_REQUIRED` |
| Solver nonzero return | `CALCULIX_SOLVE_FAILED` |
| Solver timeout | `CALCULIX_TIMEOUT`; retain available job artifacts |
| Missing/malformed DAT history | `CALCULIX_RESULT_PARSE_FAILED` |
| Last converged point below target | `CALCULIX_ENDPOINT_NOT_REACHED` |

A partial curve may report peak and initial stiffness over its converged range.
It must set `endpoint_reached=false` and
`energy_absorption_50pct_mJ=null`; the runtime never extrapolates to the target.

## 8. Analysis and BO handoff

Analysis compares real/test CAE against the parsed UTM curve using peak force,
initial stiffness, and 50%-height absorbed energy. Energy is compared only when
both sources reached the matching endpoint. The BO observation receives the
experiment objective value from Analysis; raw solver fields remain provenance
and diagnostics, not an independent fabricated experiment.

## 9. Verification baseline

On 2026-09-02:

- a 10 mm cube completed a real 50% nonlinear solve in 102 increments;
- its curve reached 5.0 mm and produced DAT, FRD, deck, manifest, and curve JSON;
- a dense 30 mm Gyroid STL (316,104 surface triangles) generated a valid
  566,686-element tetrahedral volume mesh in about 23 seconds using the direct
  discrete-surface route;
- a 180-second 30 mm Gyroid nonlinear run converged its first increment at
  0.015 mm and 101.0885 N, then timed out; DAT/FRD remained available, the
  result was partial, and 50%-height energy remained `null`.

Focused automated tests cover deck constraints, native DAT parsing, exact
endpoint handling, subprocess wiring, live delegation, deterministic scaling,
and the Analysis energy comparison.
