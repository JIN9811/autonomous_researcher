# Codex Coding Instructions — ATR LangGraph Runtime IDE

목표: 현재 임시 LangGraph Runtime Map을 실제 실행 가능한 Graph Editor + Runtime Compiler + Live Dashboard로 고도화한다. 사용자는 화면에서 노드 순서, 엣지, 모듈 내부 graph, Python handler, prompt, tool, LLM backend를 수정할 수 있어야 하며, 수정된 그래프는 실제 LangGraph 실행 순서를 바꿔야 한다.

본 지침의 기준 UI는 `atr_runtime_ide_concept_reference.png`이다. 생성된 아이콘은 `icons/`와 `icons_png/`를 사용한다.

## 0. 절대 원칙

1. GUI는 Python 소스코드를 직접 수정하지 않는다.
2. GUI는 graph/module config만 수정한다.
3. Backend는 config를 validate하고, 허용된 registry 안의 handler만 compile한다.
4. Graph 변경은 반드시 versioning, validation, dry-run compile을 거친 뒤 실행한다.
5. 기존 ATR 실행 기능은 보존한다. 리팩토링은 기능 삭제가 아니라 runtime graph를 config-driven 구조로 바꾸는 작업이다.
6. 모든 runtime event는 frontend가 이해할 수 있는 표준 schema로 emit한다.
7. 실제 장비 실행 전 simulation/dry-run mode를 지원한다.
8. frontend는 LangGraph 내부 구현을 직접 알면 안 된다. Runtime API/Event Bus만 바라본다.

Module 내부도 graph로 표현한다.

```yaml

  - source: load_objective

    target: export_stl

  - source: validate_geometry
```

### 3.3 Handler registry

Python handler는 registry에 등록된 것만 사용할 수 있다.

```python
HANDLER_REGISTRY = {
    "design.load_objective": "graphs.modules.design.nodes.load_objective",
    "design.generate_candidate": "graphs.modules.design.nodes.generate_candidate",
    "design.validate_geometry": "graphs.modules.design.nodes.validate_geometry",
    "analysis.analyze_metrics": "graphs.modules.analysis.nodes.analyze_metrics",
}
```

검증 항목:

- handler exists
- import succeeds
- callable
- signature accepts state/context
- declared input/output schema exists
- unsafe handler is not allowed in live mode

### 3.4 Graph compiler

`graphs/compiler.py` 구현 책임:

1. Load YAML
2. Validate schema
3. Resolve modules
4. Resolve handlers
5. Build LangGraph StateGraph
6. Add nodes
7. Add edges / conditional edges
8. Compile
9. Return runnable graph

Pseudo-flow:

```python
def compile_graph(config_id: str, mode: Literal["simulation", "live"]):
    config = load_graph_config(config_id)
    validate_graph_config(config)
    registry = load_handler_registry()
    graph = StateGraph(ATRState)
    for node in config.nodes:
        handler = resolve_handler(node.handler, registry, mode)
        graph.add_node(node.id, wrap_handler(node, handler))
    for edge in config.edges:
        if edge.condition == "always":
            graph.add_edge(edge.source, edge.target)
        else:
            graph.add_conditional_edges(edge.source, condition_router(edge))
    graph.set_entry_point(config.entry_node)
    return graph.compile()
```

### 3.5 Validation

`graphs/validator.py`는 다음을 검사한다.

- duplicate node id
- missing node referenced by edge
- missing entry node
- missing finish node
- disconnected node
- cycle policy: allowed/forbidden/requires_guard
- missing handler
- missing module
- input/output schema mismatch
- unsafe live device edge without Guardian
- live execution without simulation dry-run warning
- graph version conflict

## 4. LangGraph Map이 실제 기능을 바꾸는 방식

Frontend에서 노드/엣지를 바꾸면 다음 순서로 처리한다.

```text
1. User edits graph in React Flow
2. Frontend converts nodes/edges to GraphConfig DTO
3. PUT /api/graphs/{graph_id}
4. Backend saves draft version
5. POST /api/graphs/{graph_id}/validate
6. Backend returns validation results
7. User clicks Compile
8. POST /api/graphs/{graph_id}/compile
9. Compiler builds LangGraph runtime
10. User clicks Run
11. Runtime executes compiled graph
12. Events stream back to GUI
```

Graph editor에서 단순 visual edge만 바뀌면 안 된다. 저장된 YAML의 `edges`가 바뀌어야 하고, compile 결과도 바뀌어야 한다.

## 5. Module 내부 편집

## 6. Python 파일 변경 기능

사용자가 말한 “모듈 안에 들어가는 PYTHON 파일도 바꿀 수 있게”는 두 단계로 구현한다.

### Phase A: 안전한 handler selection

- GUI에서 직접 Python 코드 수정 금지
- registry에 등록된 handler를 선택
- file path, function name, docstring, input/output schema 표시

### Phase B: Advanced code editor

- 별도 advanced mode
- Monaco Editor 사용
- 저장 전 lint/test/import check
- 변경 시 새 graph version 생성
- live mode에서는 즉시 반영 금지
- dry-run 통과 후 적용

1차 구현은 Phase A까지만 한다.

## 7. Safety / Live Device 정책

Live 장비가 걸린 graph는 반드시 다음 조건을 통과해야 한다.

- Guardian node 존재
- emergency stop route 존재
- simulation dry-run 기록 존재
- device bridge health OK
- human approval required flag 처리
- unsafe tool은 live mode에서 차단

Dangerous/live tool은 config에 명시한다.

```yaml
safety:
  requires_guardian: true
  requires_human_approval: true
  allowed_modes: [simulation, live]
  live_device_tools:
    - printer.start_print
    - robot.move_to_pose
    - utm.start_test
```

## 11. Acceptance Criteria

1. 사용자가 GUI에서 edge를 변경하고 저장하면 YAML config의 edge가 바뀐다.
2. Validate가 missing node, cycle, missing handler를 잡는다.
3. Compile 후 실행하면 실제 LangGraph 실행 순서가 GUI graph와 일치한다.
4. 실행 중 active node와 active edge가 실시간으로 glow/animation 표시된다.
5. Node 클릭 시 마지막 input/output, handler, status, duration이 보인다.
6. ModuleEditor에서 agent 내부 순서를 바꿀 수 있다.
7. Handler는 registry 안에서만 선택된다.
8. Dry-run mode에서 실제 장비 호출 없이 전체 graph가 실행된다.
9. Live mode는 Guardian/safety 조건 없으면 실행되지 않는다.
10. Run 종료 후 timeline, event log, artifact lineage가 남는다.

## 12. 주의사항

- 기존 Flask/Jinja/static 구조가 있다면 한 번에 삭제하지 말고, `/legacy` 또는 compatibility route로 유지한다.
- 신규 frontend는 `/ide` 또는 root를 점진적으로 대체한다.
- backend event schema는 먼저 고정한다. frontend가 schema에 의존하므로 중간에 자주 바꾸지 않는다.
- visual graph와 runtime graph가 불일치하면 안 된다. 반드시 compile result를 frontend에 다시 보내서 최종 실행 그래프를 표시한다.
- live device bridge는 simulation adapter와 같은 interface를 가져야 한다.

## 13. 최종 제품 정의

이 작업의 최종 결과는 단순 LangGraph map이 아니다. 목표는 다음이다.

```text
Configurable LangGraph Runtime IDE for Autonomous Researcher / Self-Driving Lab
```

사용자는 이 IDE에서 실험 graph를 설계하고, agent 내부 module을 수정하고, Python handler를 안전하게 매핑하고, dry-run으로 검증하고, 실제 ATR runtime으로 실행하며, live event와 artifact lineage를 추적할 수 있어야 한다.
