# Complex Image Workflow E2E Design

## Goal

Create and execute a multi-window Equipment Skill that proves image-first replay remains reliable across file selection, form entry, processing, result verification, and result saving after every target has moved away from its recorded coordinate.

## Workflow

1. Open the workflow application.
2. Select an input file in a separate file-browser window.
3. Enter specimen ID and sample count.
4. Run deterministic analysis and wait for the completed result.
5. Open a separate save dialog, enter an output name, and save JSON.
6. Reset the application in a shifted layout and replay the compiled Skill.

## Constraints

- Use the existing Windows PyAutoGUI bridge binary without production-code changes.
- Record with `image_tracking=true` and `coordinate_fallback=false`.
- Every click must compile to inline tight/context PNG candidates without `x` or `y`.
- Keyboard input may follow the image-resolved focus target.
- Replay success requires both an on-screen completed status and a valid output JSON file.
- A missing target must fail closed with `UI_LOCATOR_NOT_FOUND`.
- Do not commit this work before user review.

## Evidence

- Saved recording and validated Equipment Skill package.
- Compiled program and bridge execution result.
- Before/after screenshots showing shifted layout.
- Output JSON generated by replay.
- Negative replay result with the target application absent.
